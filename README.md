# 屏幕实时翻译

框选屏幕上任意软件的一块区域，自动识别里面的外语（OCR）并实时翻译成中文，
结果显示在旁边的对照窗口里。**不会覆盖你的屏幕**，也不改动任何软件本身。

对照窗口是一个**真正的应用程序窗口**：有最小化 / 最大化 / 关闭按钮，边框可以
拖动缩放，磨砂玻璃质感 + 白色细边框。它不是贴在图上的透明叠加层。

## 快速开始

```
1. 双击 setup.bat   （只跑一次，装依赖约 3~5 分钟）
2. 双击 run.bat     （启动，屏幕上出现对照窗口）
3. 按 Ctrl+Alt+Z    框选要翻译的软件区域
4. 按 Ctrl+Alt+T    开始 / 暂停实时翻译
```

## 热键

| 热键 | 作用 |
| --- | --- |
| `Ctrl+Alt+Z` | 框选区域 / 重新框选 |
| `Ctrl+Alt+T` | 开始 / 暂停实时翻译 |

面板上的按钮也能做同样的事。

## 窗口

| 操作 | 行为 |
| --- | --- |
| 拖标题栏空白处 | 移动窗口 |
| 双击标题栏 | 最大化 / 还原 |
| 拖窗口四边四角 | 缩放（走 Windows 原生缩放，有贴边吸附） |
| `—` | 最小化（位置会记住） |
| `□` / `❐` | 最大化 / 还原 |
| `×` | 退出程序 |

窗口位置和大小存在配置里，下次启动自动还原；如果上次的位置已经不在
当前屏幕范围内，会自动挪回可见区域。

外观细节：

- **磨砂玻璃**：用 Windows 11 的亚克力（Acrylic）实现，能透出后面的桌面并模糊。
  刻意**只让标题栏、状态栏和边框半透明**，正文区保持不透明 —— 否则壁纸透上来，
  小号中文笔画会糊掉，实测很难读。
- **白色边框**：窗口自身的圆角与 1px 半透明白边由 Qt 样式表绘制，配合透明窗口
  背景露出后面的桌面。
- 需要 Windows 11（本机 22631 实测）。低版本会自动降级成普通不透明窗口，
  功能不受影响；所有 Win32/DWM 调用失败都静默忽略。
- 如果换了显示缩放比，边框拖拽热区会自动按 DPI 换算（本机 125%）。

窗口使用要点：

- **热键在窗口最小化后依然有效**，程序不会因为最小化而停。
- **框选时要避开这个窗口自己**（它是置顶的）——见下面「使用要点」。

## 外观（设置 → 外观）

面板的颜色、透明度、背景图都可以自己改，改完**立刻在窗口上预览**，
点「取消」会退回原来的样子。

| 可改的项 | 说明 |
| --- | --- |
| 预设 | 5 套配色，选中即套用（不会覆盖你选好的背景图和框选边框设置） |
| 面板底色 / 透明度 | 标题栏、状态栏、边框那一圈的颜色与不透明度 |
| 正文底色 / 透明度 | 左右两栏文字区的颜色与不透明度 |
| 强调色 | 「开始/暂停」按钮的颜色 |
| 文字色 / 次要文字色 | 正文与状态栏、提示文字的颜色 |
| 边框色 / 透明度 | 窗口那圈白色细边的颜色与不透明度 |
| 背景图片 | 点「选择图片…」挑一张本地图片（png/jpg/bmp/webp/gif），可选铺满/适应/拉伸/平铺，以及不透明度 |
| 磨砂玻璃 / 窗口置顶 | 开关 |

> 颜色用的是系统的取色器，透明度是 0~255 的滑杆。

## 框选范围的边框

框选（`Ctrl+Alt+Z`）之后，选中区域外面会贴一圈**看得见的边框**，
默认是橙色 3px，左上角还有一个 `1062 × 260` 这样的尺寸标签。
可以在「设置 → 外观 → 框选翻译范围时的边框」里改颜色、粗细、是否显示标签，
也可以整个关掉。

边框**画在区域外面**而不是压在上面 —— 压上去的像素会被截图抓走当文字识别。
这一圈窗口也设了鼠标穿透，框选后你不会点不到下面的软件。

## 使用要点

- **区域越小越快**：只圈住需要翻译的那部分界面（比如一个对话框），
  区域小则 OCR 快、翻译少、刷新更勤。
- **避开窗口自身**：对照窗口是置顶的，框选时不要把窗口圈进去，
  否则窗口里的中文会被当成原文反复翻译。
- **画面不变就不干活**：程序会比较相邻两帧，画面没变化时跳过 OCR，
  所以静止的界面不占算力，只有内容变了才重新识别。
  另外每 4 秒会**无条件**重新识别一次（`设置 → 翻译 → 强制刷新`），
  这是必需的兜底：画面只变了一个数字时，变化量小到测不出来
  （实测把 `Round 1` 改成 `Round 2`，像素平均差只有 0.00019，
  而阈值必须设在 0.002 以上才不会把噪声当变化），
  只靠阈值的话面板会一直停在旧内容上，看起来就像「不实时了」。
  重复的屏会命中翻译缓存，不会重复请求接口。
- **区域里全是中文时会列出原文**：译文栏会显示
  「识别到 N 段文字，但都不需要翻译」并把识别到的原文灰字列在左边，
  这样能一眼看出程序确实在识别，只是这屏不用翻。
- **短词走术语表**：`Copy` / `Settings` / `Paste` 这类界面按钮词直接用内置
  术语表翻译，比在线接口更准（接口会把 `Copy` 译成「收到」、
  `Paste` 译成「粘土」），也不消耗网络请求。
- **整句换了个更好的引擎**：默认降级链的第一位是必应中文站——它的响应里带
  `usedLLM: true`，短词和整句都比原来那家准得多（实测 42 条界面文本
  2.8 秒，全部正确）。第二位火山翻译更快（一屏 0.5 秒），必应不可用时顶上。

## 翻译为什么准一些了

在线接口对**孤立短词**和**专名**极不靠谱（`Copy`→「收到」、`Setting`→「背景设定」、
`GitHub`→「代码托管平台」、`Python`→「蟒蛇」）。所以真正送接口之前，
本地先把这几类挡下来：

| 情况 | 处理方式 | 例子 |
| --- | --- | --- |
| 短词 / 菜单项 | 查内置术语表（1297 条，Windows、Office、浏览器、开发者工具、媒体播放器、游戏、系统设置等） | `Copy`→复制、`Access denied`→拒绝访问 |
| 带尾巴的菜单项 | 先把快捷键、省略号、项目符号剥掉再查表 | `Save As...`→另存为、`Copy (Ctrl+C)`→复制、`• Paste`→粘贴 |
| 高频整句 | 43 条常见对话框语句的**精确匹配**对照表 | `Do you want to save your changes before closing?` → 关闭前要保存你的更改吗？（接口会翻成「你想在交房前…」） |
| 专名 / 代号 / 文件名 / 版本号 | 原样保留，**连接口都不发** | `GitHub`、`PDF`、`C++`、`onnxruntime`、`setup.exe`、`v1.2.3`、`win11` |
| 句子中间的代码片段 | 先挖成占位符，翻完再原样放回 | `Branch not found: origin/main` → 未找到分支：origin/main（接口会翻成「未找到分支：起源/主线」） |
| 纯数字 / 符号 | 原样保留，不发 | `50%`、`1920×1080` |
| 需要翻译的整句 | 剥掉装饰后送接口，装饰**原样拼回** | `Zoom In\tCtrl++` → `放大\tCtrl++`（快捷键不会被译成中文而失效） |
| 同一屏重复的行 | 只送一次，结果分发回每一处 | 两行相同的 `Settings` 只花一次请求 |

另外：

- **「翻译失败」不再默默成功**：接口把原文原样退回、或译文里一个汉字都没有，
  都算这一家失败，自动换下一家（以前这种假成功会直接返回，后面的接口没机会）。
- **源语言可以指定**：「设置 → 翻译 → 源语言」默认「自动识别」，但接口的自动识别
  并不可靠（实测 `Einstellungen` 满分判成英语）。如果你知道界面是英文，
  手动选「英语」质量更稳。**选韩语/俄语/阿拉伯语/泰语/印地语/希腊语时，程序会顺便
  换用对应的 OCR 识别模型**（首次自动下载 8–14 MB，见下节「多语言」）。
- **多语言互译**：源语言不限英语，目标语言也可以不是中文。中日韩、俄语、
  阿拉伯语、泰语……都能作为源或目标，见下节「多语言」。

## 多语言

程序一开始只顺着「英语界面 → 中文」，现在两边都放开了：**任何它认得的语言 → 任何接口支持的语言**。

### 源语言那边认不认，取决于 OCR 识别模型

内置的 `PP-OCRv6` 识别模型是「多语种」的，但**只覆盖拉丁字母 + 日语 + 中文**
（把它的 18708 个字符集拆开数过：CJK 汉字 15565、拉丁/标点/数字 523、平假名 86、
片假名 94、希腊 76，**一个韩文、西里尔、阿拉伯、泰文、天城文字符都没有**）。实测：

| 源语言 | 识别结果 |
| --- | --- |
| 英语、德语、法语、西语、葡语、意语、波兰语 | ✅ |
| 日语（`設定`、`こんにちは世界`、`ダウンロードに失敗しました`） | ✅ 一字不差 |
| 中文 | ✅ |
| 土耳其语 `İndirme` | ⚠️ 大写点 İ 被认成 i |
| 越南语 | ⚠️ 声调符号丢光 |
| 希腊语 / 印地语 / 泰语 | ⚠️ 只认出零碎几个字母 |
| 俄语 / 乌克兰语 / 韩语 / 阿拉伯语 | ❌ 整行为空 |

所以在「设置 → 翻译 → 源语言」里选**韩语 / 俄语 / 乌克兰语 / 阿拉伯语 / 波斯语 /
泰语 / 印地语 / 希腊语**时，程序会去 ModelScope 下载对应的识别模型
（`korean_PP-OCRv5_rec_mobile.onnx` 13.5 MB、`eslav_…` 7.9 MB，泰语/印地语/希腊语/阿拉伯语同族），
下载一次就留在本地（`.venv\Lib\site-packages\rapidocr\models\`），之后离线可用。
模型下载好之前，状态栏会写「韩语识别模型」之类的字样；加载失败会自动退回内置模型并提示。

> 别指望「自动识别」能自己换模型。检测框是**与文字体系无关**的（18 种语言 18/18 框得准），
> 但「框出来了却认不出字」这个信号只能抓到**整行为空**的那几种（俄/乌/韩/阿/泰），
> 抓不到「认出来了但全是乱码」的那几种（希/印/越）。**知道界面是什么语言就手动选，最稳。**

### 指定源语言还有一个好处：日语里的汉字

日语界面上有一堆**纯汉字**的行 —— `設定`、`編集`、`表示`、`終了`、`保存`。
它们的文字体系和中文一模一样，按「看起来已经是中文就跳过」的规则会被整行丢掉，
可它们的日文意思恰恰是「设置 / 编辑 / 显示 / 结束 / 保存」。

所以只要你**明确把源语言选成日语**（而不是「自动识别」），程序就不再拿文字体系
猜了，直接信你：

| 设置 | `設定` | `我喜欢的音乐` |
| --- | --- | --- |
| 源语言=自动识别，目标=中文 | 跳过（当已经是中文） | 跳过 |
| 源语言=日语，目标=中文 | **翻成「设置」** | 翻（按日语翻，可能是错的） |

代价是：源语言选日语又指着一屏中文时，那些中文会被当日语送出去翻一遍。
**知道界面是什么语言就选什么语言，这是最省事也最准的用法。**

### 目标语言

「设置 → 翻译 → 目标语言」有 16 项：简繁中文、英、日、韩、俄、德、法、西、葡、意、
阿拉伯、泰、越南、印地、印尼。选非中文时有两条行为差异：

- **术语表不生效**。那是份「英译中」的软件界面对照表（1297 条），目标不是中文时用了反而错
  —— 实测中文→日语曾把 `Settings` 译成「设置」。
- **「跳过已经是目标语言的文本」**（原来的「跳过已经是中文的文本」）按目标语言判断：
  目标是日语时，一行日文会被跳过，一行中文不会。

### 实测（`tools\_verify_multilang.py`）

```
日语 ダウンロードに失敗しました → 下载失败        （内置模型）
德语 Herunterladen fehlgeschlagen → 下载失败      （内置模型）
韩语 다운로드 실패 → 下载失败                     （韩语识别模型）
英语 Download failed → 下载失败                   （内置模型）
中文 设置 / 下载失败 → Settings / Download failed （目标=英语）
中文 → 日语                                       （目标=日语）
全部通过 ✅
```

第三种情况换语言包要重新加载模型（首次含下载约 2 秒），之后每屏只多几十毫秒。

- 菜单层级写法会保留空格：`File > Save` → `文件 > 保存`。
- **代码片段不会被翻译**（可在「设置 → 翻译 → 保护代码片段」关掉）：URL、Windows 路径、
  `./` 相对路径、`origin/main` 这类 git 引用、`user_id` 这类变量名、版本号、十六进制、邮箱，
  发送前都会被换成 `{{0}}` `{{1}}` 占位符，译文回来后再原样换回去。
  占位符形式是实测挑的：接口会原样保留 `{{0}}`、`##0##`、`❶❷`，
  但 `$0$` 会丢掉末尾的 `$`、私有区字符（U+E000）会变成乱码，所以都不能用。
  万一某个接口把占位符吃掉了，这一条会用**不带占位符的版本重发一次**
  —— 最坏情况退化成「origin/main 被直译」，但绝不会丢内容，也不会把 `{{0}}` 漏到界面上。

想看校准效果，跑 `tools\calibrate_translate.py`（加 `online` 参数会真的打接口）。

## 翻译接口

按顺序自动降级，前一个失败就试下一个：

| 顺序 | 接口 | 说明 |
| --- | --- | --- |
| 1 | 必应翻译（中文站） | 质量最好，免费无 key。实测 42 条界面文本 2.8 秒，短词全对（`Sign in`→登录、`Now playing`→正在播放），连德语 `Einstellungen` 也能自动认成「设置」 |
| 2 | 火山翻译接口 | 快得多（一屏 0.5 秒，48 条仍 0.8 秒），短词在术语表兜底下同样全对；短板是自动识别不可靠，所以当必应挂掉时的高速替补 |
| 3 | 微软 Edge 接口 | 唯一**真批量**接口，最稳；短词差（`Copy`→「收到」），但短词基本都被术语表挡在前面了 |
| 4 | MyMemory | 逐条送、匿名每天 5000 字符，仅作最后兜底 |
| — | 大模型接口 | 质量最好，需要自己填 API key，默认不勾选 |
| — | Google 接口 | 中国大陆直连不通，仅在你配了代理时自动启用 |

在「设置」里可以勾选/取消接口，勾选顺序即降级顺序。

> **必应和火山用的都是网页版自己调用的接口**，不用 key、不用登录，但微软/字节
> 随时可能改动或下线（2026-07 微软刚下线了旧的 `edge.microsoft.com/translate/auth`，
> 返回 404；更早的 `bing.com/ttranslatev3` 也一度只回空体）。真到那天，在设置里
> 取消勾选换一家即可，无需改代码——这也是为什么降级链留了四家。
>
> 有道 demo 接口（`aidemo.youdao.com`）已被官方限流（前 4 条能用，第 5 条起
> 返回 `errorCode=411`），已从默认链里去掉，但保留在可勾选列表里应急。
> `api.deeplx.org/translate` **不能**加进来：它无 key 时返回 200，但 `data` 字段
> 是一条推广链接，形状很像成功，进了降级链会造成静默假翻译。

### 免费接口现在能翻到什么程度

通用机器翻译在**成句**上本来就不错，问题出在**软件界面的短文本**上。以下都是
实测结果（`tools\quality_probe.py` 跑出来的原始输出）：

| 原文 | 早期免费接口给的译文 | 中文软件里的说法 | 现在 |
| --- | --- | --- | --- |
| `Now playing` | 正在演奏 | 正在播放 | ✅ 术语表已修 |
| `Shuffle all` | 全部洗牌 | 随机播放全部 | ✅ 术语表已修 |
| `Show less` | 显示更少 | 收起 | ✅ 术语表已修 |
| `Lyrics not available` | 歌词未公开 | 暂无歌词 | ✅ 术语表已修 |
| `Load last save` | 加载最后存档 | 读取上次存档 | ✅ 术语表已修 |
| `Controller disconnected` | 控制器断开连接 | 手柄已断开 | ✅ 术语表已修 |
| `Track my order` | 跟踪我的订单 | 查看订单 | ✅ 术语表已修 |
| `Branch not found: origin/main` | 未找到分支：起源/主线 | 找不到分支：origin/main | ✅ 占位符保护已修 |
| `Build succeeded with 3 warnings.` | Build成功了，但收到了3次警告。 | 生成成功，有 3 个警告。 | ✅ 换必应接口已修（构建成功，但有 3 条警告。） |

短词错译的根源是**逐条独立翻译、没有语境**：实测把整屏文本连成一整段送过去，
结果与逐条发送**逐字相同**（`Now playing` 两种方式都得到「正在演奏」），
所以靠「加语境」救不了，只能补术语表或换引擎。整句则是**换引擎**解决的：
必应中文站的响应里带 `usedLLM: true`，等于背后挂了个大模型。

### 什么时候才需要配大模型接口

上面那张表现在免费接口已经全绿，所以**日常使用不需要配**。但如果你经常遇到
这些情况，配一个大模型接口会更稳：

- 界面是**非英语**（德语、法语、俄语……），而免费接口的自动识别认错语种——
  实测必应认得，火山会把德语 `Einstellungen` 音译成「埃因斯特伦根」。
- 整段**长句、说明书式文字**（免费接口在 40 字以上的句子上偶尔会漏词）。
- 想让它按你的习惯用语（比如「保存」还是「存储」）统一口径。

大模型只要在提示词里说清「这是软件界面、按中文软件的习惯说法」就能翻对，
DeepSeek 的价位大约是每百万 token 一两块钱（屏幕翻译一天几万 token 级别）。
在「设置 → 翻译 → 大模型接口」里填 key 即可：

- **接口地址**：任何 OpenAI 兼容地址，填到 `/v1` 为止。
  本地 [Ollama](https://ollama.com) 填 `http://localhost:11434/v1`（key 随便填）。
- **模型**：如 `deepseek-chat`、`qwen-plus`、`gpt-4o-mini`。
- **API key**：只存在本机 `%APPDATA%\ScreenTranslator\config.json`，不会上传别处。

没填 key 时这一家会被**自动跳过**，不影响免费接口的降级链。
想让它优先生效，去设置里把它**勾选**并移到列表最上面。

## 词典

主面板上有第二个页签「词典」，鼠标停在屏幕上的英文单词上还会弹出小卡片。
词库是 **ECDICT**（MIT 协议，约 63 MB 的 CSV，首次在设置里点一下自动下载，
之后转成 53 MB 的 SQLite，收录 **40 万条**）。整件事**完全离线**，
查词不联网、不消耗接口额度。

### 三种取词方式

| 方式 | 怎么用 | 适合 |
| --- | --- | --- |
| 面板「词典」页 | 自动跟着屏幕区域里认到的词走，也能自己输入查 | 一边翻译一边顺手看 |
| 鼠标悬停取词 | 鼠标在屏幕上的单词上停 0.45 秒，弹一张小卡片 | 不想离开正在看的窗口 |
| 独立词典窗口 | 面板上的「独立窗口」按钮，带「生词本」页签 | 系统地看、整理生词 |

悬停卡片是**不接受焦点、也不吃鼠标事件**的置顶窗口 —— 鼠标移到卡片上也
不会把你在用的窗口弄失焦（不做这一步的话，一悬停就会「抢焦点」，很难受）。

### 词条卡片上有什么

- **音标**、**柯林斯星级**、牛津核心词标记
- **考试标签**：中考 / 高考 / 四级 / 六级 / 考研 / 托福 / 雅思 / GRE
- **词频**：COCA 词频第 N 位，带一句「最常用 1000 词 / 常用 3000 词 /
  常见 10000 词 / 一般书面语 / 较少见」的白话说明
- **不同语境的不同意思**：ECDICT 的释义按 `n.` `v.` `[网络]` 分成一条条义项，
  程序会**结合屏幕上那句话猜词性**，把最可能的那条排到第一位
  （`run` 在「I run a small company.」里动词义项排第一，在「The run was long.」
  里名词义项排第一）
- **变形**：复数 / 过去式 / 过去分词 / 现在分词 / 比较级 / 最高级
- 词形对不上时会提示原形（`running → 原形 run`）

> 「变体占位」有个坑：ECDICT 里 `Settings` 自己也是一条记录，释义却只有
> 一句「设置（setting的复数）」，而原形 `setting` 那条才有「环境 / 背景 /
> 布景 / 镶嵌 / 调整 / 一副餐具」和「设置」。所以直接命中之后还要看一眼，
> 认出这种凑数记录就改用原形那条。

### 生词本

卡片上的「☆ 收录到生词本」把词连同**当时那句话**一起收进去。生词本里能：

- 标记已掌握 / 删除、看每个词查了几次、在屏幕上出现过几次
- **导出 CSV**：十二列（单词 / 音标 / 词性 / 释义 / 考试 / 来源句子 /
  句子译文 / 收录时间 / 查询次数 / 出现次数 / 掌握 / 笔记），带 BOM，Excel 直接打开不乱码
- **导出 Anki 卡片**：写好 Anki 导入头（`#separator:Comma` / `#html:true` /
  `#columns:Word,Back`），在 Anki 里「文件 → 导入」后字段对应 Word / Back 即可

存储位置 `%APPDATA%\ScreenTranslator\vocab.jsonl`（一行一个 JSON，坏行自动跳过）。

### 词典设置（设置 → 词典）

| 项 | 默认 | 说明 |
| --- | --- | --- |
| 启用词典 | 开 | 总开关，关掉就不建库、不取词 |
| 鼠标悬停取词 | 开 | 关掉就只剩面板和独立窗口 |
| 悬停延迟 | 450 ms | 鼠标要停多久才弹卡片 |
| 卡片字号 | 10 pt | 悬停卡片的字号 |
| 卡片宽度 | 280 px | 悬停卡片的宽度（220–360） |

同一页里能看到词库状态（「词库已就绪：400,847 条，53.3 MB」）、
下载进度条和「下载并建立词典库 / 重建」按钮。下载支持**断点续传**，
中途卡住了再点一次会接着下。

## 识别引擎

RapidOCR（ONNX Runtime），模型随安装包内置，**首次运行不需要联网**。

推理设备在「设置 → 翻译 → OCR 推理设备」里选：

| 选项 | 同一张 281×412 界面截图 | 常驻内存 |
| --- | --- | --- |
| **省内存（CPU）**（默认） | 中位 **276 ms** | 引擎约多占 48 MB，**整个程序约 240 MB** |
| 更快（显卡 DirectML） | 中位 **109 ms**（快 2.5 倍） | 要多占约 300 MB，**整个程序约 517 MB** |

> **为什么默认选慢的那个**：DirectML 多占的约 300 MB 是**永久**的 ——
> 实测把 OCR 引擎对象删掉再 `gc.collect()`，那 300 MB 也只还回来十几 MB，
> 要等进程退出才释放（这是 DirectML 自己的分配行为，不是泄漏）。
> 而轮询间隔默认 1.5 秒，CPU 这边 276 ms 完全跟得上，实测实时循环
> OCR 260–269 ms、面板照常刷新。**想要更跟手就切到 DirectML，代价是内存。**
> 显卡不可用时 DirectML 会自动回落到 CPU。

> 反直觉之处：ONNX Runtime 的 CUDA 版在动态输入下比 CPU 还慢，
> 所以要做 GPU 也是用 DirectML 而不是 CUDA。

### 程序占多少内存

实测（`tools/_mem_report.py`，真实代码路径，实时循环跑完后的工作集）：

| 阶段 | 省内存（CPU） | 更快（DirectML） |
| --- | --- | --- |
| 解释器 + numpy + PySide6 + core | 56 MB | 56 MB |
| 建好面板/热键/托盘窗口 | 143 MB | 143 MB |
| 加载 OCR 引擎 | 231 MB | 289 MB |
| 第一次识别 | 238 MB | 516 MB |
| 实时循环跑完 | **239 MB** | **517 MB** |

真正的大头只有两个：**DirectML（约 300 MB）** 和 **词典的 SQLite 连接
（几 MB，按需读页）**。词典库 53 MB 是文件，不会整块读进内存。

## 已知问题与排查

- **热键没反应**：`Ctrl+Alt+T/Z` 可能被别的程序占用，日志会打印
  `[hotkey] 注册失败`。改 `%APPDATA%\ScreenTranslator\config.json`
  里的 `hotkey_toggle` / `hotkey_mark`（格式如 `ctrl+shift+t`）。
- **一直显示「翻译失败」**：多半是网络问题。跑 `tools\selfcheck.py`
  看哪个接口通。降级链全部失败时面板会显示具体错误。
  必应和火山都是网页版在用的接口，双双挂掉通常是你这边的网络出口变了。
- **短词老翻错、整句也差**：先去「设置 → 翻译」看看降级链是不是还停在旧顺序。
  程序会自动把已知失效的旧顺序（`edge, mymemory, youdao, ...`）迁移到
  `必应 → 火山 → Edge → MyMemory`；如果你自己调过顺序，程序不会多管，
  这时手动把「必应翻译中文站」拖到最上面即可。
- **装了代理**：程序检测到 `HTTPS_PROXY` 等环境变量后会自动把 Google
  接口加到链尾。
- **配置损坏**：删掉 `%APPDATA%\ScreenTranslator\config.json` 即可恢复默认。
- **界面中文乱码（cmd 窗口）**：`.bat` 已存为带 BOM 的 UTF-8；
  若仍有问题，用 `run.bat` 启动（无控制台窗口，不受代码页影响）。
- **没有磨砂玻璃 / 变成纯色不透明**：窗口创建时打印一行
  `[glass] 应用结果 {...}`，三项 `dark_title` / `rounded` / `acrylic`
  应全为 `True`。若 `acrylic` 是 `False`，说明系统没开透明效果
  （设置 → 个性化 → 颜色 → 透明效果），或不是 Windows 11。
- **界面突然变成系统浅色主题、按钮全白**：样式表解析失败。
  改 `ui/panel.py` 的 `PANEL_STYLE` 时注意：**里面的注释只能用
  斜杠加星号成对包裹，不能用井号开头** —— 井号在 CSS 里是 ID 选择器，
  解析器会把它当成畸形选择器，并丢掉它之后的整段样式表。
- **词典查不到词 / 一直提示去下载词库**：设置 → 词典 看状态。
  没建库就点「下载并建立词典库」；已经下过一半会**接着下**。
  建完不用重启，程序会自动重新接上。
- **悬停取词不弹卡片**：先确认设置 → 词典里「鼠标悬停取词」是开的，
  再把「悬停延迟」调小。卡片只在**确实认出这个词**时才弹
  （估不出鼠标落在哪个词上就不弹，宁可不弹也不弹错词）。
- **某个词的释义不对**：ECDICT 是开源词库，个别条目有错（比如它把
  `cached` 的词形映射到了 `cach`）。程序已经能识别「某某的复数」这种
  占位释义并改用原形；真遇到错得离谱的，改 `tools\_fetch_ecdict.py`
  下下来的 CSV 后点「重建」。
  这个坑实测让标题栏、按钮、状态胶囊的配色全部失效过。
- **选的背景图没显示**：确认「设置 → 外观 → 背景图片」选中的文件还在原位置。
  图片是每次启动时按路径重新读的，拖动或删除文件后需要重新选一次。
- **框选边框挡住了鼠标点击**：正常情况不会 —— 边框那一圈窗口设了鼠标穿透。
  如果确实点不到下面的软件，把「框选边框」关掉再试。
- **某些词翻译得不对**：短词和菜单项直接改 `core/glossary.json`
  （键必须是小写、不带标点），改完重启即可生效。整句的翻译质量由接口决定，
  选择「源语言」比依赖自动识别更稳。
- **面板像是不刷新了**：先看译文栏。如果写着「识别到 N 段文字，但都不需要
  翻译」，说明程序在正常工作，只是这块区域里都是中文（外语才需要翻）。
  如果连这句都没有、状态栏的耗时也一直不动，跑
  `tools\_diag_live2.py` 看实时循环有没有推进；确认是画面变化太小时，
  把「设置 → 翻译 → 强制刷新」调到 2000ms、或「变化灵敏度」调到 1‰。
- **帧率/耗电**：强制刷新间隔越短越耗电（每轮 OCR 约 100–280ms，
  走 DirectML 时 GPU 占用很低、但要多占约 300 MB 内存）。笔记本上用电池时
  建议 5000ms 以上。
- **内存占用偏高**：去「设置 → 翻译 → OCR 推理设备」确认选的是
  **省内存（CPU）**。换成 DirectML 会让整个程序从约 240 MB 涨到约 517 MB，
  而且那块内存要等退出才还。另外面板窗口本身（含磨砂玻璃）大约占 90 MB，
  关掉「设置 → 外观 → 磨砂玻璃」会少一些。
- **想给项目瘦身**：`tools\_prune_venv.py` 能算出 `.venv` 里哪些东西
  根本没被加载过（`dry` 只看不动，`apply` 把文件挪到 `%TEMP%\translate_prune`
  而不是删除，`restore` 随时搬回来）。

## 开发注意

- **面板样式表的坑**：`QSplitter::handle` 这类规则写在面板级样式表里会被
  Qt 静默丢弃，必须用 `setStyleSheet` 直接设在 handle 控件上（见
  `ui/panel.py` 的 `_style_splitter_handles`）。`QAbstractScrollArea`
  的 viewport 同理，染不到，只能在代码里设调色板。
- **不要用 `QWidget.grab()` 判断外观**：透明区域在 grab 出来的图上会变成
  白色，看到的配色是假的。判断真实外观要抓屏幕像素
  （`tools/_probe_window.py` 的 `sample_pixels`）。
